# Result Dossier multi-case qualification campaign

## Objective

Earn or falsify a public claim that Vela can present an exact,
correction-aware scientific case record faster and with no more authority
error than an information-matched flat repository dossier.

## Current state

Erdős 264 content recovery is perfect in three first-party iterations, but the
registered time improvements—5.2%, 6.7%, and 19.1198%—all fail the 20% gate.
`observatory.v9` remains noncanonical, inactive, and undeployed.

The Erdős 730 external-proof boundary is now accepted locally through an
attributed human Decision and replays exactly at repository root
`sha256:821cf0d94778f647305107943572f4916a6cf63fe5ea12506a471fabc07b7474`.
Its rooted post-Decision handoff makes construction of case two the active work
package. This does not open recruitment or activate the projection.

## Active implementation tranche

- Add Erdős 730 through the existing removable dossier declaration boundary.
- Generalize only code shared with Erdős 264; add no protocol object or writer.
- Bind the exact external and Formal Conjectures sources, producer report,
  source-first Verification, human Decision, toolchain boundary, dependencies,
  repository roots, and post-Decision handoff.
- Add an information-matched flat case and exact answer key.
- Prove deterministic HTML, JSON, print, keyboard, and no-JavaScript behavior
  from one inactive release candidate before freezing the human design.

## Entry gate

Do not begin recruitment until:

- Erdős 264 remains exactly replayable;
- the Erdős 730 boundary reaches Decision or documented deferral;
- shared Dossier code renders both cases without case-specific authority logic;
- each case has matched flat information and exact answer keys; and
- HTML, JSON, print, keyboard, and no-JavaScript outputs are deterministic.

## Frozen design

Before sessions, record:

- reviewer eligibility and recruitment channel;
- a sample-size and sensitivity calculation, with at least eight fresh
  qualified reviewers unless the calculation requires more;
- case-blocked random assignment with no reviewer seeing both presentations of
  one case;
- exact start/stop timing, timeout, exclusion, and missing-data rules;
- eight common recovery fields plus case-specific fidelity questions;
- authority/Standing errors as a hard safety endpoint;
- exact failure, caveat, discrepancy, dependency, and nonclaim scoring; and
- positive, neutral, and negative reporting language.

## Release gate

- zero Dossier-arm authority or Standing errors;
- every common field recovered correctly;
- no omitted material caveat, failure, discrepancy, or shared dependency;
- preregistered median time at least 20% below the matched flat arm;
- no case-specific material regression hidden by pooling; and
- one deterministic release root binds HTML, JSON, print, cases, and source
  Frontier commits.

## Output

If the gate passes, activate the SELECT-only v9 release, preserve v8 for
rollback, deploy, and publish only the bounded usability claim. If it fails,
retain the result and either revise once for a named observed defect or retire
the public Dossier claim.

## Nonclaims

No adoption, general productivity, scientific acceptance, external
independence, or causal Vela lift follows from a small multi-case usability
study.
