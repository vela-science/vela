# ADR 0036: Flagship mathematical breakthrough campaign

- Status: Accepted — 2026-08-03
- Protocol effect: none
- Scientific authority effect: none; only an attributed human Decision changes
  Standing
- Product effect: replaces architecture-completion work with one bounded
  discovery, correction, and inheritance proof

## Context

Vela's protocol foundation is sufficient for evidence intake, scoped
Verification, attributed Decision, deterministic replay, correction, and exact
next-work projection. The remaining risk is that the system is technically
correct but scientifically inconsequential or empirically unproven.

Four observations determine the next pass:

1. OpenAI's public Astra release reports ten research advances, publishes long
   manuscripts and Lean certificates, and claims resolutions of Erdős 146,
   180, and 183. Candidate discovery is becoming abundant.
2. Vela has positive first-party handoff cases, but they are too few and too
   related for a general productivity claim.
3. The Erdős 264 definition change is a real externally maintained semantic
   correction with downstream consumers and a bounded native Lean repair.
4. The 1,217-problem Erdős corpus contains genuine open problems, prior failed
   routes, formal statements, prizes, and machine-checkable opportunities. It
   can support a real discovery attempt without inventing a benchmark world.

Continuing to add Registry, Atlas, graph, package, runner, or policy machinery
would not answer the decisive question:

> Does exact, correction-aware Frontier state help a replaceable producer make
> and safely inherit a consequential scientific advance?

## Decision

Run one flagship campaign with three linked scientific episodes:

1. **External breakthrough inheritance:** exactly map and independently check
   the complete `openai/ten-proofs` release while keeping checker passage,
   statement fidelity, novelty review, community acceptance, and local Standing
   distinct.
2. **Real correction inheritance:** complete the Erdős 264 source correction,
   native Lean repair, Decision, replay, remap, and fresh-producer handoff.
3. **Fresh discovery:** preregister a leakage-screened candidate pool, select
   one research-level problem before model output, and attempt a novel theorem,
   counterexample, witness, or bounded advance under a native verifier.

Erdős 203 is the initial primary discovery candidate because a finite
two-dimensional cover would settle its existential question positively, an
exact certificate can be independently checked, and the pinned exploratory
campaign already contains a corrected lattice kernel, a viable prime pool,
failed routes, and a precise structured-construction obligation. The earlier
99.98% coverage result remains explicitly retracted. Erdős 647 and Erdős 7
are frozen reserves, never post-output substitutions.

The exact problem surface is the merged upstream Formal Conjectures declaration
at commit `50ee83fa7dc31c99c03c83f04be90b7fea37d314`. The exploratory
`lean-proofs` campaign is a separate evidence source. Open pull requests and
fork branches remain attributed candidates until merged or independently
frozen; they are never silently promoted to upstream state or Standing.

The campaign uses Codex or another native agent for work, Harbor for execution
and matched evaluation, native mathematical tools for checking, Git Frontiers
for canonical state, and Vela only for the evidence-to-Standing boundary.

## Evidence levels

Results use three explicit levels.

### Instrumentation

Repeated calls may validate custody, telemetry, and scoring. They always carry
`claim_credit: false`.

### Real scientific case

One source-bound correction or discovery may support a case study when it has
an exact source cutoff, native verifier, scoped Verification, human Decision,
replay, remap, and cold-successor action. It does not establish statistical
lift.

### Confirmatory product evidence

Claim credit requires unique scientific episode and lineage roots, matched
information, at least two task families, a producer/model swap, the complete
registered sample, zero authority errors, family-consistent effects, and one
qualifying real correction case.

## Consequences

- Vela will attempt genuinely new mathematics, but does not become a theorem
  prover or autonomous-scientist product.
- The Astra release becomes a recognizable inheritance stress test rather than
  a collection of automatically accepted Claims.
- Erdős 264 becomes the correction benchmark; it earns no novelty credit.
- Erdős 1056 remains useful control-plane evidence but cannot be the sole
  scientific benchmark.
- Failed discovery attempts are retained and can improve the next obligation;
  they are not silently excluded.
- A positive paper claim requires both scientific consequence and statistically
  honest continuation evidence.
- A neutral or negative result causes simplification, not a new subsystem.

## Rejected alternatives

### Build a Vela theorem-solving agent

Rejected. Agent capability is replaceable and already supplied by native
systems. Vela's durable control point is correction-aware Standing and
inheritance.

### Treat all ten Astra results as accepted

Rejected. Native build, formal fidelity, novelty, expert review, external
registry state, and local authority are different facts.

### Declare success from one impressive run

Rejected. One case can establish feasibility and scientific consequence, not
causal generality.

### Repeat one fixture until statistically significant

Rejected. Calls sharing one episode or lineage cluster are not independent
scientific units.

### Build a global Atlas or Registry first

Rejected. The current root-bound projection is enough for this campaign. New
infrastructure must be earned by a named failed query or consumer.

## Review

Revisit this decision after the campaign publishes a positive, neutral, or
negative result. Retain only the components that improved exact scientific
movement, correction recovery, or scarce expert judgment.
