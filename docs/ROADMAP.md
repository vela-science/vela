# Vela roadmap

Vela is version control for living science:

```text
map -> target -> work -> submit -> verify -> decide -> remap
```

The [active campaign](CAMPAIGN.md) owns exact phases, metrics, evidence, and
stop conditions. This roadmap records only product sequence.

## Proven foundation

- Four mathematical Frontiers replay from canonical Git repositories.
- Submission and Verification append evidence without changing Standing.
- Only an attributed human Decision changes Standing.
- Five bounded human Decisions have replayed across the current evidence base.
- A root-bound Math Source Registry and read-only Atlas project exact source
  and Frontier state without becoming authority.
- Three first-party Harbor tasks produced exact task-specific handoff gains;
  one Astra source-fidelity task failed its frozen exactness gate.
- Vela owns no agent runner, scheduler, graph database, hosted authority,
  package registry, or second writer.

These facts establish a serious state and authority substrate. They do not yet
establish a new discovery, general productivity lift, or external adoption.

## Now — flagship mathematical breakthrough campaign

One campaign must connect scientific consequence to product evidence:

```text
Astra release map
+ real Erdős 264 correction
+ one fresh discovery attempt
+ cold-successor inheritance
+ matched Harbor confirmation
```

### 1. Freeze

- Pin Vela, four Frontiers, Harbor, Astra, source registries, and literature
  cutoff.
- Correct stale paper and campaign counts.
- Freeze a leakage-screened discovery shortlist and native verifier before
  model output.

### 2. Complete Erdős 264

- Preserve the completed human Decision on the exact source correction.
- Confirm strict replay and the remapped repair Target.
- Fresh-agent repair of `Erdos264.erdos_264.parts.i` under the corrected
  integer-valued definition.
- Separate native Lean Verification.
- Matched Git/files versus Vela-guided Harbor case.
- Exact successor obligation.

This is the qualifying real correction case, not a novelty claim.

### 3. Complete the Astra release map

- Bind all ten advertised result families and twelve Comparator profiles.
- Reproduce native checks in the hardened offline environment.
- Complete statement-fidelity matrices for Erdős 146, 180, and 183.
- Keep novelty, field review, source status, local Decision, and downstream
  inheritance distinct.

### 4. Attempt a fresh result

- Primary candidate: Erdős 203, using its merged Formal Conjectures statement,
  corrected exploratory campaign, and exact affine-cover verifier.
- Fixed reserves: Erdős 647, Erdős 7, and one Astra-derived downstream
  obligation.
- One long-horizon native-agent campaign, all failures retained.
- Native verifier and separate scope/literature review.
- No post-output target substitution.

A new theorem, counterexample, exact witness, or meaningful bounded advance is
success. A clean null is useful evidence but not a breakthrough.

### 5. Decide and inherit

- Present one consequence-complete Decision packet.
- Human accepts, rejects, or defers.
- Replay and remap the exact outcome.
- Give the next valid obligation to a different producer or model family.

### 6. Confirm or falsify lift

- Unique scientific episodes, not repeated model calls, are the units.
- At least two task families and one producer/model swap.
- Full preregistered sample, initially 40 balanced blocks.
- Guided exactness noninferior, zero authority errors.
- Restricted time-to-exact point ratio at most 0.80 and upper 95% confidence
  bound below 1 for useful lift.
- Real correction precision, recall, route survival, and stale-use gates pass.

### 7. Publish at the evidence ceiling

- A concise canonical Vela paper explains scientific state, correction-aware
  authority, and one vivid end-to-end result.
- A separate evidence companion holds roots, methods, fixtures, failures,
  costs, and reproducibility.
- Positive, neutral, and negative outcomes are publishable.

## Deferred until earned

- hosted Registry or package marketplace;
- Vela-owned agent runner or campaign scheduler;
- graph database, vector store, or universal ontology;
- new Frontier or repository for one source release;
- package manager or shared adapter SDK;
- empirical-domain expansion;
- protocol feature release unrelated to a reproduced campaign blocker.

## Product gate

The next product surface must help a cold researcher answer:

1. What exactly stands?
2. Why does it stand?
3. What does this correction affect?
4. What exact action is valid next?

If a CLI or Observatory change does not reduce time or error on one of those
questions by at least 20 percent, do not ship it.

## Breakthrough gate

Vela earns the stronger action-complete Frontier claim only when:

- one consequential real result or correction completes the full loop;
- a different producer inherits the exact next obligation;
- matched state causes family-consistent improvement under honest sampling;
- correction preserves every independent route and rejects stale inheritance;
- independent reproduction succeeds; and
- authority, scope, and source truth remain exact.

Otherwise retain the useful scientific-state infrastructure and delete the
unsupported discovery claim.
